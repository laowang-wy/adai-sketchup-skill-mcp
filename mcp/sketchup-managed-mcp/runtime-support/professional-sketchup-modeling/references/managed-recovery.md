# 恢复与窗口证据

先核对当前目标进程、原操作回执和真实文档；保留未保存工作。结果未知先用返回的 `next_call` 查询或恢复原操作，不换 ID 重放。

`evidence_pending` 表示已提交几何仍在，通常只用 `sketchup_project_retry_evidence` 补图。若 SU 已退出并重新打开检查点，使用 `sketchup_project_recover(action=restore)`：程序核对本次冻结检查点的文件哈希、实际路径和当前对象身份，成功后按返回动作重取证；不重新执行几何。存在未决写操作时先恢复原回执。

`failed_confirmed` 且 `rollback_confirmed=true` 表示本次构造已撤回：从返回的脚本行、几何对象和错误类型修正输入后再 step。它不是未完成的写请求，也不是截图故障；原样重交同一错误脚本不会修好模型。

普通 `ready_for_step / review_required` 检查点恢复也由 `restore` 核验。已审完最后阶段的 `ready_to_finish` 可恢复同一封存末阶段检查点，再接续 `finish`；程序核对文件与当前文档，不重建几何或重写旧审核。结果未知且确认退回原封存检查点的情况，按工具返回的专用动作处理；不能把仍在运行的写请求当作已经失败。实际几何已变化或文件不匹配时保留现场与诊断，使用当前恢复动作，不手改签名状态。

原生取证会保存并恢复相机。只导航视口不会把旧图冒充新图，也不应使未变几何的封存证据失效；图像文件、对象身份和几何仍需通过核对。当前成果变化则重取证、重新看图。

受管项目、独立验证视图和模型审计预览在 SU 2019 及以下默认从当前渲染缓冲导出，避开部分驱动的离屏 OpenGL 崩溃；窗口须至少 640×480，图像记录实际视口尺寸。需要诊断其它驱动时可用本机环境变量 `SKETCHUP_EVIDENCE_RENDER_BACKEND=image` 恢复离屏导出，或 `framebuffer` 明确选择缓冲导出。导图完成或失败均恢复当前相机；窗口太小或图像写入失败会返回错误，先处理该原因再补图。其它 SU 版本保留原生离屏方式；新机器和未实测版本仍需验证。

配置 `window_print` 时优先窗口取证，失败记录回退原因并使用原生方式。恢复相机、选择或目标窗口失败时停止；空白图、错误文档和旧截图不能作为当前证据。
