# 专家操作：建筑系统，而非教学阶段

新专家项目使用受管工作单元。一个单元是一组有共同控制的构件，如墙洞窗、屋盖与承托。六阶段是建筑经验地图，帮助专家理解构造顺序和检查重点；新建的体量、代表组件必须依次单独构造、实际看图并审核，通过后才可合并、调整其余阶段。程序维护该起步状态；无需额外证明表，已有历史项目沿用保存策略。

直接使用当前 Skill 与 `project_begin` 返回的共同建筑判断；不要重复加载共同底座。照片任务先建立整栋体量及可比视角，来源、轮廓或构造有疑点时才定向读一份方法。体量单独审核，不以构件框架替代主形；随后在真实宿主上构造完整代表组件，核对连接与可编辑性并独立审核。两步通过后可合并后续执行与审核，无需新增表格。

古建照片任务先用来源核对返回的 construction_brief；已提供的相关经验直接用于构造，不再重复检索。短卡不足以处理当前屋面、斗拱或接缝时，再用 sketchup_ref 定向读取相关经验。根据来源选择生成器或受管 Ruby，不把案例名或预设当成形制结论。

## 构造与修改

`sketchup_project_step` 接收 **ruby_file 或 operations 二选一**。直接构造可参考[操作参数](scoped-operations.md)；复杂曲面、古建或未覆盖算子仍用既有生成器与受管Ruby，不强迫套固定模板；需要 helper 时读取 `references/ruby-snippets.md`，它是构造参考，不是额外审核表。程序校验生命周期、身份与真实作用范围，专家不因算法名或边数少被拒。

体量和代表组件审核通过后，一次可完成一个完整建筑系统或其余小模型内容；也可以连续多笔提交后再一起检查。每笔有独立事务和原回执，不能称多笔整体原子。默认追加；`update`用于现有系统，`replace`明确替换选中系统。替换不删除别的单元；用户手改或共享定义影响越过当前单元时拒绝并保留现场，而不是扩大到整个文档覆盖。

目前保护以**整个选中单元**为可写范围，不是任意面级授权编辑器。相关共享对象宜在同一系统内组织；合法自定义脚本仍必须遵守用户授权。已审核单元也可以直接更新，但旧成果审核失效，需核对新结果。

## 取证与合并审核

完成有意义的构造后调用 `sketchup_project_retry_evidence`。在新专家项目里它同时是正常的当前成果取证入口，不必制造一次失败来获取图片。默认当前参考视图；可用 `views`选择 `reference/perspective/front/side/plan/underside` 的相关组合。程序附参考图和机器读回，不固定每次五视图。

查看返回的实际图片后调用 `review`，通常只提供 `visual_review.state/observations/inspected_views`。图片可用返回的键，如`reference`、`geometry_whole_front`；不能列未实际查看的图片。尺寸、源图、空腔、关键连接与材质按当前任务一起核对，不为凑通道另开数轮。

一份当前成果证据可覆盖之前多笔操作。当前版本对任意新写入采用保守的**当前项目审核失效**，不假装已掌握完整的跨对象视觉依赖图；下一次仍由专家选择必要视图，不自动重跑全部截图。每次写入的保护/结果确认与看图审核是分离的。

返修只给具体观察，程序保存问题和证据关系。下一步直接修正授权单元并取新证据；若原判断有误，也可以用新证据与实际观察纠正，不需写够字数或提交空操作增加计数。未重查的问题不自动消失。关键执行未知始终先查原回执。

需要独立意见时 `status(section=review_packet,question=...)` 返回原任务引用、原始来源、当前证据和问题，不把建模者自评当依据，不默认启动另一个Agent。`status`不写模型、不生成图片。

## 交付与边界

当前成果实际检查通过后调用 `finish`；无需六次审核或假造阶段完成记录。缺少机器测量可明确未验证，不能声称已机器认证。已知真实缺项/错误仍须修正。

`status(section=task)`才读取任务全文；普通状态不重复任务书。长期历史在文件里，当前返回只带必要问题和下一步。
