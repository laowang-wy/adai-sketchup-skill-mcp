# 用户指定的中间楼阁样本

源文件：廊架古建1221qq2757429261微信同号 (1).skp。2026-09-12只读提取；读取前后SHA256一致。

用户截图指定中间楼阁上层屋顶作为歇山视觉目标。实际定位：根实例C0111，上层屋顶G0366。已看提取屋顶透视派生图，与截图布局对应。派生图不是SketchUp渲染，省略材质与孔洞。

正身屋面经G0335/G0286定位到C0029与C0030重复条带；转角另有C0025/C0028及相关构件。正身条带的布置是平行移动，不能沿用全宽向短正脊收拢的瓦列方案。C0029/C0030是源模型条带表现，尚不能据面数称为完整单瓦搭接模型。

檐下斗拱阵列G0328含28个正身C0042和4个转角C0044。两种原型实际几何已提取并看过透视图。C0042展开164面，C0044展开252面；这只是源几何计数，不证明木构接触正确。C0044包含斜向支路，不能只旋转C0042生成转角。共用斗块定义C0000，以及不同短构件定义，提供可复用工具的拆解依据。

user-corridor-reference.json保存根实例与各级定义、完整父变换。user-corridor-world-sections.json对一条正身条带和一条盖瓦条带组合全部变换，只用于模型尺寸与剖面研究，非历史实物测绘。

更新：本样本已进入 source_template_tool.py 的源组件重建路线，完整屋顶在 SU2019 通过重建并查看透视/山面/檐下，记录见 validation/source-corridor-xieshan-d/review.json。正身和转角件已提取为独立入口。源样板只接受等比缩放与放置；这不等于已将其推导成自由比例歇山算法，也不证明全部构件承托面接触正确。不得将此前推定预设冒称由本样本测得。
