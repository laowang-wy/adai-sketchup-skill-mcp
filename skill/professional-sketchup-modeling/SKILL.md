# ADAI SketchUp 建模

依据用户资料创建或修改准确、可编辑的 SketchUp 模型，持续推进到可核验交付。默认使用 `guided`；只有任务第一条非空行完整匹配 `ADAI老王，开启专家模式` 或 `开启ADAI老王专家模式` 才使用 `autonomous`。两种模式共享建筑判断和构造方法；差别是推送多少、由谁组织后续操作。

## 起手：先得到可执行短卡

使用当前绑定的本包 Skill 与 MCP，不混读同名旧副本。先调用 `sketchup_runtime(action=startup)`，只读一次精炼短卡；再用 `status`、`ping` 和 `model summary` 核对真实进程、文档和已有项目。多实例先 `instances` 再 `select_instance`；目标不唯一、实例变化或结果未知时停下重选，不重试、不猜测。保护未保存工作，绝对路径打开或切换文档。

随后调用 `sketchup_project_begin`。它必须把来源观察、当前可执行的建筑方法、关键参数、常见错误、检查视角和下一步动作直接放进返回卡；正常建模不要求 Agent 先 `list → match → read` 才能得到方法。方法卡是怎么认、怎么建、参数怎么调、怎么看和失败后怎么换方法，不是登记或数量门槛。

## 来源路由与具体动作

实际查看用户图片、CAD 或模型，区分可见事实、推导、假设和未知；透视像素不能直接当真实尺寸。先识别主体、屋面形式、结构体系、层间关系、退台和负空间，再建模。

- 图片重建：逐张看图，先写主体轮廓、宽深比例、层级关系、屋面/檐线、开敞空间和遮挡；用 `project_begin` 返回的候选方法，不用空泛的通用盒体路线。
- 中式楼阁、塔、黄鹤楼或古建照片：默认走古建图片构造卡。若卡片返回 `si_shan`，按以下顺序执行：
  1. `sketchup_ancient_tool(action=preset,family=roof,preset_id=si_shan)`；用返回参数按来源调整 `width/depth/rise/eave_height/setback/corner_lift`。
  2. `sketchup_ancient_tool(action=compile,family=recipe,parameters=returned_preset)`；`compile` 已包含参数校验。
  3. 使用返回的 `ruby_file` 调用 `sketchup_project_step`。
  4. 实际看正面、侧面、斜视和檐下视图；先修完整主形、屋脊/檐线、翼角和廊下负空间，再组织楼层重复和斗拱、瓦、栏板等构件。
  已有匹配方法时不得为了省一步改写成自定义 Ruby；只有卡片明确说明方法范围不足，才换表示方法并说明原因。
- CAD：先确认单位、图层、轴线和可见边界，再按 CAD 经验卡的动作顺序构造，不把图层名称当实体。
- 普通建筑或现有 SKP：先锁定用户已认可的体量和对象，再按当前问题选择最小修改方法。

## 建筑判断与主形

先完成“完整主形”：主体 + 定义性屋面 + 退台/收分 + 主要负空间 + 开敞关系。台基、墙盒、柱网、楼板或平板不能替代歇山、悬山、曲屋面、翼角和退台；去掉装饰和颜色后仍应能辨认来源形体。主要比例必须来自可核对的参照、模数或图注；没有可靠绝对尺寸时保留相对比例和假设。

古建屋面按来源分区核对正身、山面、侧坡、正脊/垂脊、檐线和翼角；不同层屋盖不能默认缩放同一模型。复杂曲面优先使用已有受管构造和共享边界方法。不要用登记记录、对象数量、面数、bbox 或材质代替形态判断。

## 执行、纠错与模式

内部阶段字段保留兼容性；Agent 看到的第一项是“完整主形”，古建定义性屋面在这一步完成，不把 `roof_profile` 当成必须另开的一轮。guided 按当前返回的动作卡逐步提交；autonomous 可以合并相关建筑系统、连续组织构造和授权返修，但仍先完成完整主形再进入构件。

默认可执行链保持旧版的动作顺序：
`project_begin → 来源观察/方法卡 →（古建时 preset → compile → ruby_file）→ step → 实际看图 → review → 下一项`。
六项工作含义仍是：完整主形；一个代表性构件和转角；确认后的重复实例；来源特有变体；表皮与细部；最终证据和交付。可以按来源把相邻项合并，但不能跳过完整主形，也不能先用台基、墙盒或柱网代理块冒充主形。每次只把当前动作、依据、关键参数和下一步返回给 Agent，避免让它自己从经验包里猜路线。

Ruby 先落盘，使用 `PipClawManagedBuild.build(entities, context)`；不在脚本中保存、开关文档、改引擎状态或嵌套事务。能由程序可靠完成的对象定位、重复构造、回执和恢复由 MCP 负责，模型专注来源理解、方法选择、几何构造和看图纠错。

每次 `step` 后从与来源对应的视角检查当前问题，列出最多三个真正影响下一步的偏差并修改相应参数。连续两轮无改善就回查来源、构造方法或坐标，改变方法。用户已认可的主形和关键参数锁定；局部修改只影响目标构件及接触关系，保留可回退版本。

写请求结果未知时先查原 `operation_id`；已提交但取证失败只补证，不重建、不换 ID 重放。视觉结果记录 `matched`、`mismatch` 或 `not_checked`；形态不符就返修，不能补登记绕过。工具成功、几何合法、视觉相符和文件交付分别表述。

## 交付

只有 `finish` 返回 `finished`、实际交付文件存在且对应证据可核对时才报告交付。明确列出来源事实、推定部分、主要缺陷和未实测项。默认只汇报实际变化、观察、阻碍和下一步。
