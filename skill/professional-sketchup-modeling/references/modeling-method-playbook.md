# 建模方法：从参考约束到可复查的组件

适用：新建、图片重建、CAD 建模及既有模型修改。与当前受管 API 和建筑类型规则一起执行。这里传递的是可观察、可验证的操作方法，不是模型内部推理或能力保证。阶段记录应是简短的依据、参数、决定和检查结果，不要求写长篇思考过程。

## 最小工作循环

**看证据 → 写约束 → 定义宿主和参数 → 构建当前尺度 → 读回与对照 → 修正或推进。**

每次只解决当前尺度最重要的未知问题。用实际照片和读回值纠正假设；不以成功运行、自己先前写的文字或看起来合理的模板替代依据。用户指出的缺陷进入回归清单，后续检查关联实例，不能修完后只看远景。

## 开工前：一份短的建模工作记录

阶段记录只保留当前阶段的依据、参数、决定和检查结果；不要建立额外运行时表单或把开发工作簿写入受管证据目录。

1. **目标与视距**：交付主体、可编辑层级、整体/近景要求、已知单位和尺度依据；没有测量依据时写相对比例，不编造精确尺寸。
2. **参考覆盖**：给参考图编号，记录能证明的部位、遮挡与视角。主视图控制主要投影，侧/仰/斜上方控制进深及屋顶连接。不同照片可能有透视、时代或修缮差异，不能直接平均像素尺寸。
3. **约束表**：每条约束给出来源位置、observed/derived/assumed/unknown、值或范围、单位和检查方法。高风险未知项先验证，低风险背面推断明确标记。未知不自动等于需要问用户；先利用现有证据推进不受影响部分。
4. **构件关系**：写宿主、子件、重复家族及特殊情况，列标高链和局部坐标。例：梁底决定墙顶，柱轴决定承托中心，檐曲线决定封檐/椽/瓦边界。禁止各部件独立猜坐标。
5. **参数来源**：共享尺寸/曲线由一个版本化参数源生成，记录依赖项。示例数字不能复制成工程数据。

## 先抓决定外观的形体

以轮廓、比例、负空间、层间节奏和接触关系排序，再做饰件。先选最能暴露错误的正立面、严格侧面、檐下或剖面，不只选择漂亮的透视角。对比时固定参考视角；先确认相机正确，再归因几何。照片存在透视缩短，屏幕高度不能直接当真实层高。

当信息不足以定传统屋顶或斗拱制式时，描述可见部件和连接，不用名称倒推全部造型。对 CAD 保留原始定位与单位；对自由设计把用户约束与设计选择分开；运行 test 模式不需要捏造照片依据。

## 分阶段决策卡

| 阶段 | 先作决定 | 必须看到的证据 | 失败处理 |
|---|---|---|---|
| massing / source_alignment | 主要体块、开口、参考相机/源坐标、层檐标高、保留实体核边界 | 对照图、轮廓和宽高比、主要负空间；CAD 的定位/旋转/单位读回 | 修改骨架或相机，不加细节遮掩 |
| archetypes | 完整可重复开间、固定尺寸细件与可变尺寸部分、独立转角/高首层例外 | 真实原位样板；正面/侧面/仰视；柱头接触、窗墙梁底、开口深度与曲面收口 | 修样板；只验证标准层不能代表所有楼层 |
| replication | 实例数、首末范围、父级变换、已放置原型是否计入 | 首/中/末、对侧和转角；完整变换及重复位置检查 | 复制错误修复制；已接受原型错误走受管独立项目纠正 |
| variants | 源证据要求的不同点及受影响宿主 | 独立变体、对比相邻普通实例、边界连接 | 不为一个变体修改所有共享兄弟 |
| facade_detail | 尚未由重复系统承担的一次性细节 | 下/中/上近景，牌匾文字，檐口、入口、节点收口 | 分类错误回到所属尺度；不以堆叠细件掩盖主形错误 |
| finish | 材质、组织、交付主体、剩余未知和保存/重开方案 | 最终整体与局部、文件与证据、旧根清单；独立报告重开状态 | 未检查不声称通过；保存不等于已验证还原 |

修改任务先列“用户指的对象—现状证据—目标约束—受影响依赖—验证视图”。沿依赖关系修改最小范围，同时验证邻接对象；未授权的其它项目根保持原样。

## 原型接口审查：先验证局部，再验证安装和接缝

对于需要拼接的重复系统，原型证据应覆盖组件局部视图、实际宿主样板、相邻两件接缝和必要的端头/转角。可在当前受管原型接口组合中组织两件验证用子实例；这不是全楼阵列，不允许修改已接受阶段或越界创建模型。记录真实出现次数，复制时避免重叠。

用现有 MCP 原型证据检查节点；若自动视图未覆盖接缝，按受支持的受管证据能力补齐。无法取得必要视图时标记未验证，不能直接导图绕过受管流程，也不能因创建了组合就声称接口通过。

接口记录包含对象路径、坐标系、接口种类（轴线、端点、平面、方向或允许间隙）及检查方法。记录一种接口不等于实现了对应测量器；当前离线检查器仅支持其明确列出的数值检查。包围盒相交不能证明平面/曲面贴合，未知关系保持 unsupported/unverified。

## 错误定位：每轮提出一个可检验原因

| 看到的症状 | 优先检查 | 有效修正方向 |
|---|---|---|
| 承托歪、变宽或偏柱轴 | 全父级变换、方向轴、镜像、截面法向与厚度中心 | 分离刚性细件，修宿主坐标和挤出方向 |
| 下层墙矮、梁下空带 | 每层墙顶/梁底、统一限高、完成面和窗头 | 按层标高推导，拆分亮子/墙带，保留真实通廊 |
| 窗洞不见或看起来贴片 | 遮挡体量核、窗洞进深、楼板和侧壁 | 修实体/空洞及依赖尺寸，不靠前移玻璃 |
| 瓦和檐口错位或穿透 | 不同脚本的曲线版本、偏移、法向和共享边界 | 共用曲线采样，各层独立厚度和偏移 |
| 原型正确，复制后错误 | 二次变换、父级缩放、首末重复、对侧方向 | 检查真实实例路径，修复制变换 |
| 越改越复杂仍不像 | 最早的形体假设、屋顶连接、参考是否被正确读取 | 停止堆细节，修改抽象；记录拒绝方案避免重试同一假设 |
| 运行超时或证据失败 | 原请求是否仍运行、当前绑定与证据状态 | 按恢复规则处理；不要把执行故障归因造型或重放几何 |

先保留前一轮证据；改变最小相关参数集，记录预期结果；重新看同一个暴露问题的视角，再看关联区域。不要同时改相机、材料和几何后宣称找到了原因。修正是否有效由新证据决定。

## 具体例子：把用户意见变成检查项

“下面两层的墙体高度不够”不是执行“把整层拉高”。先记录下两层墙顶、梁底和照片中的开口关系；排查统一限高；再调整墙/亮子等分段及关联楼板。复查两层严格立面和檐下、上层未受损、通廊未误封。

“斗拱歪了”先拆成可观察问题：朝向、缩放、厚度偏心还是组合错误。检查真实世界变换和柱轴；剖面法向统一后测厚度；核查梁座接触。曲形承托仍按参考身份命名，不把一块曲板当成完整传统斗拱。

## 检查记录与效率

- 每次审查只需记录对象/视图、依据、观察或测量结果、通过/失败/未知、下一步。空白模板、漂亮文字或填满字段不能使 MCP 审批自动通过。
- 把几何数值交给 `validate_geometry_measurements.py` 的已支持检查；真实表面接触、照片相似度和历史制式仍需专业视觉判断。缺测量不算合格。
- 优先修重复次数多、占轮廓大、处于承托/标高依赖上游的错误；在完整原型阶段做足验证，减少复制后的返工。
- 按目标视距控制瓦、窗格和栏杆细度；分别计唯一几何和实例展开代价，不把模型更大当成更好。
- 当前 MCP 任务卡的 `method` 是版本化操作提示，随 begin/step/review/status 返回；它不新增自动几何验收或改动已签名状态。常驻旧进程需要正常重新加载后才读到新卡片，不中断正在运行的写入。

## 能力边界与验证

这些方法降低记忆、规划和漏检负担，但不能保证不同模型具有相同视觉识别能力。要评估提升，应在相同参考、工具、时间预算和交付要求下比较独立任务：轮廓/标高错误、节点缺陷、返工次数、可编辑组织、交付完整性；评分者查看实际模型与证据。不得用离线测试通过宣称弱模型建模能力已达到某个模型水平。
